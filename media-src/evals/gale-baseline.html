Every turbine, every sensor, ten times a second.

Gale is an open-source time-series database built for wind-farm telemetry. One node ingests 3.6 million sensor readings a second and keeps years of SCADA history queryable in milliseconds.

300 turbines × 1,200 sensors × 10 Hz= 3,600,000 readings a second

That is one large offshore wind farm. Gale writes all of it on a single machine, and keeps writing at the same speed on day four hundred as on day one. Here is how.

  1. Sorted at the turbine

    Readings leave a nacelle interleaved: pitch, then temperature, then vibration, then pitch again. Gale’s edge agent groups them by sensor before they are sent, so each series reaches the server already in time order. There is no out-of-order merge on the write path.

  2. Compressed as columns

    Within a series, timestamps are stored as the change in the gap between readings, and values as the bits that differ from the previous reading. Sensors that sample steadily compress hard: a 16-byte reading lands on disk as about 1.3 bytes.

  3. Appended, never rewritten

    Each second of a turbine becomes one immutable block at the end of a log. There is no per-point index to update, so the cost of a write stays flat whether the archive holds a day or a decade.
